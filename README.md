# aiken-media-relay-auth

A.I.KEN Studio（Codex・Claude Code・ChatGPT から使う MCP 中継サーバー。画面に出る名前は「A.I.KEN Studio」で、リポジトリ名・関数名・URL などの内部の名前は従来のまま）のログイン・許可画面です。
ChatGPT・Codex・Claude Code の接続の操作から開かれ、Google アカウントでログインして接続を許可します。

- `consent.html`：Supabase Auth の OAuth 2.1 サーバーの許可画面（authorization path）。名簿に登録された人だけが先へ進める
  - 戻り先（ChatGPT〔chatgpt.com〕か、この PC のアプリ〔Codex・Claude Code など。ループバック〕か）を大きく出し、接続しようとしているアプリの名前は 40 文字までで「（登録された名前。正しいとは限りません）」を添える（名前は接続アプリの登録で誰でも決められるため）
  - 「人から送られてきたリンクでは許可しない」「許可したあとの画面の URL を人に送らない」の注意を出す（ループバックのときは「いまこの PC で、あなたが自分で Codex・Claude Code などのアプリを操作していて、その流れで開いた場合だけ許可する」も）
  - 許可・拒否（許可済みで戻るだけのとき・使えないアカウントのときも）のあと、すぐにログアウトする。方式はファイルの冒頭の定数 `CONSENT_END_SESSION`（下の「公開の前の注意」）
  - ログインを始めてから・許可の画面を出してから 5 分でログインを終える（時刻の記録が無いときも終える）。画面を離れる（タブを閉じる・別のページへ移る）ときもログアウトする。Google のログインへ移るときだけは、戻ったときに要る PKCE の code_verifier を残す
  - 他のサイトに埋め込まれたときは表示しない
- `admin.html` / `admin.js` / `admin-lib.js`：管理コンソール（「名簿」「回」「設定」の 3 画面。名簿の管理、使用量・最終アクセスの確認、回と会場・AIKENメンバーの月額・クレジット追加の設定、利用の上限とモデルのオン・オフ・変更の履歴。管理者だけが使える）
  - 「回」は DB の 013（回と会場）、「設定」は DB の 014（app_settings）と Edge Function `admin-api`（`GET /models`）が前提。公開は 013・014 を本番に適用してから行う
  - 013 の適用前に開いた場合：名簿の上に「013 がまだ適用されていない」案内が出て、「回」の画面はその旨のエラーになる。受講者の追加は回を設定せずに行える（`cohort_id` は送らない）が、回の設定・まとめての回の設定はエラーになる
  - 014・`admin-api` の前に開いた場合：「設定」の各欄に「014 がまだ適用されていない」／「サーバーに接続できない（通信の問題か、admin-api がまだ用意されていない可能性）」と出る（名簿・回は使える）
  - 「設定」のモデルのオン・オフ：モデルごとの一括スイッチ（見出しの行の右端。切り替えられるモードがすべてオン／オフ／一部）と、その下にモード（テキストから・画像から 等）ごとのスイッチがある。一括スイッチを押すと、オフ・一部ならすべてオン、オンならすべてオフ（サーバー側で無効のモードは変わらない）。モードが 1 つだけのモデルは一括スイッチだけ。保存する値は従来どおりモデル ID の配列
  - 「設定」のモデルのオン・オフに、**区分ごとのタブ**（全体／受講者／AIKENメンバー。DB の 015〔role_models〕と admin-api の `role_enabled_models` が前提）。どのタブも、モデルごとの一括スイッチ＋モードごとのスイッチ（モードごとのスイッチは普段は閉じていて、右端の ▸ ボタンかモデル名を押すと下へ開く。一部だけオンのモデルは閉じていても「一部」と「2 つのうち 1 つ」で分かる。切り替えが 1 つだけのモデルはスイッチ 1 つだけ）。
    - 全体のタブは今までどおり（`enabled_models`）。受講者・メンバーのタブでは、全体でオフ（または環境変数で無効）のモードは押せない（「全体でオフ」と出る）。区分の一覧が null のあいだは、全体でオンのモードがすべてオンに見える。
    - **区分のタブで、カタログのすべてのモデルがオンになると null（全体と同じ）として保存する**。つまり、これから足すモデルもその区分で使えるようになる。1 つでもオフなら、オンのモデルの一覧を保存し、これから足すモデルはその区分ではオフになる。今のカタログに無い古い ID を外すだけの保存は、明示の一覧のまま保存する（null にはしない）。null（制限なし）に戻すには「制限なしに戻す」を使う。このボタンは、保存されている一覧が明示（null でない）あいだは、全部オンに見えても出る（「今は一覧で決めています。新しく足したモデルは自動では使えるようになりません」と添える）。**受講者の制限を使う間は、受講者の一覧を明示（1 つ以上オフ）にしておく**（null のまま高いモデルをカタログに足すと、受講者にも使えるようになるため）。
    - 全体のタブには、受講者・メンバーの一覧が設定されている（null でない）ときだけ「受講者の一覧が設定されています。…」の 1 行が出る。管理者には区分の制限はかからない（全体の設定に従う）。
    - 保存は 1 つのボタン。変えたタブの分だけを 1 回の `admin_update_settings`（履歴 1 件）にまとめる。確認の文はタブごとに、オン・オフにするものを並べる。保存の直前の読み直しは 3 つの一覧のどれかが変わっていたら保存しない。保存で使えるモデルが 0 になる区分（全体のタブの変更で受講者・メンバーが 0 になる場合を含む。保存前から 0 の区分は除く）があると、追加の確認が出る（全体が 0 になるときは全体の 1 件だけ）。
    - 古いサーバー（015 の前の admin-api・DB）では、区分のタブと下の「1 回の生成の上限」の欄は出ない（全体のタブだけ今までどおり）。
  - 「利用の上限」に **1 回の生成の上限（クレジット）**（1〜10,000 の整数。空欄で保存すると「上限なし」＝null。環境変数の既定は無い）。管理者を含む全員の 1 回の生成に効く。値を入れる・下げる・なくすときは確認が出る。表示はクレジットだけ（ドルは出さない）。
  - お知らせ（保存の結果・エラー）は、画面の上部（スマホは中央、PC は帯の下の右寄せ）に浮かぶトースト（position: fixed。本文や上の帯を押し下げない。シートの上にも重なる）。成功・お知らせは 5 秒で自動で消え、エラー・警告は × で閉じるまで残る（マウスを乗せている間・フォーカス中は消えない）。最大 3 件を縦に積み（あふれたら成功・お知らせから古い順に消し、エラー・警告は残す）、同じ文が続けて出たら ×回数 にまとめる。PC 幅では上の帯にかからないよう帯の下の右寄せに出す
  - 運用の注意：モデルを「全部オン」にすると「制限なし（`enabled_models = null`）」として保存する。そのため本番では `ENABLED_PROVIDER_MODELS`（環境変数の上限）を必ず設定しておく。未設定だと、後でカタログに足した高いモデルが自動で有効になる
  - 30 分操作が無ければ（最後の操作の記録が無いときも）ログアウトする。「ログアウト」はこのコンソールのセッションだけを切る（scope local。管理者本人の ChatGPT・Codex の接続は切らない）
  - 入力の範囲は DB（014）の天井に合わせる：全体の 24 時間の額は $10〜$10,000（2026-10-19 に $2,000 から変更。DB は `202610190000200_global_daily_cost_range.sql`）、クレジットの追加は 1 回 1〜10,000（1 人・今の枠への追加の合計も 10,000 まで）、回の期間ごと・メンバーの月額は 0〜10,000
- `index.html` / `mypage.js` / `mypage-lib.js`：マイページ。**トップ（`/`）で開く**（2026-10-19 の作り直し。設計 `docs/proposal-web-redesign.md` の 10 章。以前の `mypage.html` は `index.html` に名前を変え、`/mypage`・`/mypage.html` は `vercel.json` の rewrites で同じファイルを出す。転送はしない）（ログイン中の本人の「残りクレジット」と「使えるモデルと目安単価〔クレジット〕」を見る。履歴・枠の予定・1 日の回数は出さない。ドルの金額・「1 クレジット＝$0.01」の換算は出さない）
  - **作り直しの構成（2026-10-19）**：見た目は共通の `studio.css`（下）、見せ方は Canvas にそろえる。上から、残りの主カード（残り・「/ 上限」・棒・残りが少ない／無いときの印と文・今の段階・枠と期限・「段階ごとの枠・持ち越しなし」・［Canvas を開く］）→ 折りたたみ「今日の段階」「使えるモデル」（初めはどちらも閉じる。広い幅〔880px 以上〕だけ 2 列）→ 折りたたみ「つなぎ方」（README の MCP の URL と Claude Code の手順。Codex の手順は未掲載）。開閉の状態は保存しない
  - **メールアドレスは画面に出さない**（2026-10-19 田口さんの決定）。右上は区分の印とログアウトだけ。**例外は名簿に無いとき（403）の画面だけ**で、違うアカウントで入ったと気づけるよう「このアカウント（…）は登録されていません。」とログインしたメールアドレスを出す（同日 main の決定。メールはセッションのもの）
  - ［Canvas を開く］は `/canvas` を別のタブで開く普通のリンク（`target="_blank"`・`rel="noopener noreferrer"`。「別のタブで開きます」を添える）。押しても何も送らない。マイページの守り（離れたときのログアウト・30 分の時間切れ）はそのまま
  - 読み直し：初回・失敗の画面の［もう一度試す］・主カードの ⟳（読み上げの名前「最新の状態を読み込む」）。最後に成功した時刻を「確認 HH:mm」（日本時間）で出す。**タブがまた見えたとき**（Canvas から戻ったときなど）は、時間切れを確かめたうえで、ログイン中・本人の画面・前回の成功から 30 秒以上なら 1 回だけ読み直す（`shouldReloadOnReturn`）。一定間隔の自動の読み直しはしない。要求には番号を振り（`createRequestCounter`）、古い応答・ログアウトのあとの応答・別のアカウントの応答では画面を変えない。番号は読み込みの最初の await より前に取り、認証の確認のあと（トークンの更新を待つことがある）と応答のあとの両方で照らす。ログアウトを始めたら（`hideContent` → `close()`）、以後は新しい番号を取れない（Codex TASK-0087 の F1。回帰試験は `scripts/mypage_logout_race_nodetest.mjs`）。本人の画面からの更新に失敗したときは、画面・開いた詳細・フォーカスをそのままにし、主カードに理由・「表示は HH:mm の時点のもの」・［もう一度試す］を出す（成功の時刻は進めない）
  - ログイン前の画面は、トップの役目（Google の OAuth のアプリのホームページ）も持つ：サービスの説明・使える人・Google でログイン・プライバシーポリシー・利用規約・サービスの案内（`/about`）。ログアウトの説明は「ログインについて」の折りたたみへ移した。supabase-js を読めないときも、この画面をボタンを押せない形で出す。スクリプトが動かないときのために `<noscript>` にも説明とリンクを置く
  - 表示は最小限（2026-10-16 田口さん：情報過多なので不要な文字は排除）：残りクレジットは大きな数字・「/ 上限 N」・バー・枠の説明 1 行（「ブリッジワーク期間・10/22 まで」「今月・10/31 まで」）。管理者は「上限なし」、枠の外は 1 行の案内だけ。使えるモデルは種類（動画・画像・読み上げ・音楽）ごとに「モデル名」と「目安」だけ（既定の解像度で、動画は 5 秒・画像は 1 枚・読み上げは 1,000 文字・音楽は 1 分または 1 曲。数字は「目安はクレジット」と見出しの横に 1 回だけ書く）。既定のモデルに「既定」、画像からしか作れないモデルに「画像から」の印。並びは既定が先頭、あとは目安の安い順
  - データは Edge Function `user-api`（`GET /me`。読み取り専用）から読む。`user-api` が先にデプロイされていないと「読み込めませんでした」になる（下の「マイページの公開」）
  - ログインは Google（`prompt: select_account`、戻り先はこのページ）。セッションは sessionStorage（鍵は `aiken-mypage-auth`。ほかの画面とは共有しない）。30 分操作が無ければログアウトし、「ログアウト」はこの端末のセッションだけを切る（scope local）。
  - **ログアウトと再読み込み（研修用の Mac の使い回しの守り）**：画面を離れると必ずログアウトし、再読み込みのときだけ Google のログインを自動でやり直す。ログインを「残す」のではなく、毎回ログアウトして入り直す作り。
    - 画面を離れるとき（pagehide。再読み込み・タブを閉じる・別のページへ移る）：画面の中身を消し、保存済みのアクセストークンでこの端末だけのログアウト（`/auth/v1/logout?scope=local`、keepalive）を送り、`aiken-mypage-auth` で始まる項目をすべて消す。そのうえで「再読み込みの手がかり」（`aiken-mypage-reload-hint`。sessionStorage。`{ leftAt: 離れた時刻, hadSession: 離れる前にログインしていたか }`。トークンは入れない）を書く。Google のログインへ移るときは何もしない（戻ったときに要る code verifier と時刻の記録を残す）。
    - ページを開いた時点（supabase-js が読めるかの確認より前。fetch と storage だけ）：保存済みのセッションが残っていれば、そのトークンでログアウトを送ってから `aiken-mypage-auth` で始まる項目を消す（`?code` 付きのときも送る。そのときは Google の往復に要る code verifier と操作時刻だけ残す）。supabase-js が読めなくても、この消去は必ず走る。
    - そのあと `mypage-lib.js` の `decideOnOpen` で決める：`?code` 付き → 今までどおりログインを完了。**再読み込み**（`performance.getEntriesByType("navigation")[0].type === "reload"`）で、手がかりがあり、`hadSession` が true で、離れてから 15 秒以内 → 「ログインし直しています…」と出して、`signInWithOAuth`（Google、戻り先はこのページ。アカウント選択の `prompt` は付けない）を**自動で 1 回**呼ぶ。それ以外（普段に開いた・タブを閉じて開き直した・復元・手がかりが無い／ログインしていなかった／古い／未来・戻る進む）→ ログイン前の画面。手がかりは判定のあとに必ず消す（自動のログインを繰り返さない）。自動のログインに失敗したときと、Google の画面で取り消して戻ったときは、ログイン前の画面で止まり、自動ではやり直さない。
    - Google から `?code` で戻ったのにログインを完了できなかったとき（code の交換の失敗）は、URL の `?code` と code verifier を消して、ログイン前の画面に「ログインを完了できませんでした。もう一度ログインしてください。」を 1 行出す。自動のログインはしない。
    - 戻る・進むでキャッシュ（bfcache）から表示されたとき（pageshow の persisted）は、再読み込みではないので自動のログインはしない：手がかりを消して読み込み直し、ログイン前の画面になる。
    - 30 分操作しないで時間切れになったあとは、再読み込みしても自動ではログインし直さない（離れる前に時間切れだった場合は、手がかりの `hadSession` を false にして書く）。
    - 運用の注意：自動のログインは「その Google アカウントがブラウザにログインしたまま」だから戻ってこられる。つまり再読み込みでは、Google にログインしているアカウント（前の人のアカウント）で入り直す。**使い回しの Mac では、利用が終わったら Google のログアウトも運用で行う**（マイページのログアウトでは Google のログインは切れない）。Google のアカウントが複数あるブラウザでは、Google の選択画面が出る。タブを閉じて 15 秒以内に「閉じたタブを開き直す」と、ブラウザによっては再読み込み扱いになり自動のログインになり得る（その場合も Google にログインしているアカウントで入る）。
    - ログアウト・30 分切れでは、通信を待つ前に画面の中身を消す。
  - 状態：ログイン前／読み込み中／名簿に無い・停止中（「利用登録が確認できません。管理者にお問い合わせください。」）／通信の失敗（「もう一度試す」）／本人の画面からの更新の失敗（主カードの中に理由と「もう一度試す」）
